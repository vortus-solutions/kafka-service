# CR-0002 — Detecção de consumer parado e aviso de argumentos ignorados

**Data:** 2026-08-25
**Solicitante:** usuário (feedback de consumidores da lib, incl. photon-engine)
**App Version:** 2.0.9 → 2.1.9
**Status:** implemented
**Urgência:** medium
**Domínios afetados:** saúde do serviço, envio, documentação de upgrade e referência
**Spec relacionada:** nenhuma

---

## Descrição da mudança

Cobrir quatro lacunas reportadas por usuários da v2:

1. **Alto** — a remoção do `error` com `type: 'consumer_crash'` não estava
   documentada no guia de migração.
2. **Médio** — `getHealth()` não permitia detectar um consumer parado.
3. **Baixo** — a documentação apontava para a versão `2.0.7`, nunca publicada.
4. **Baixo** — argumentos extras em `send()` / `sendBatch()` eram ignorados em
   silêncio.

## Motivação

O ponto 1 é uma perda de capacidade silenciosa: uma aplicação que trata
`type === 'consumer_crash'` migra sem erro de compilação, sem teste quebrado e
sem log, e fica sem rede de segurança. O guia agravava isso ao listar `error`
entre o que é preservado.

O ponto 2 é a contrapartida: sem um sinal de saúde do consumo, todo serviço
consumidor precisa alcançar `kafka.consumer.assignment()` por fora do wrapper —
integração que o próprio `API_REFERENCE.md` classificava como avançada.

## Comportamento atual

-   `getHealth().connected` só volta a `false` em `disconnect()` explícito; o
    retorno nunca indica um consumer que parou de receber partições.
-   `send(topic, messages, opts)` e `sendBatch(batch, opts)` descartam o argumento
    extra sem qualquer sinal em runtime.
-   `docs/LIB_UPGRADE.md` e `docs/API_REFERENCE.md` estão titulados para `2.0.7`.
    O npm tem `1.0.0`, `1.0.1`, `1.0.2`, `2.0.2`, `2.0.3`, `2.0.4`, `2.0.5` e
    `2.0.9`.

## Comportamento desejado

-   `getHealth()` inclui `partitionsAssigned`.
-   `send()` / `sendBatch()` avisam uma vez por método quando recebem argumentos
    extras.
-   A documentação nomeia a versão em que estas mudanças são publicadas e trata
    o sumiço de `consumer_crash` como transformação obrigatória.

### Backend

`getHealth()` passa a chamar `consumer.assignment()` a cada invocação, dentro de
`try/catch`. O método lança quando o consumer não está conectado; nesse caso, e
quando o processo não criou consumer, o campo vale `null`.

## Decisões necessárias antes de implementar

**Escopo:** `consumer_crash` não é reintroduzido. O cliente Confluent não expõe
listeners de instrumentação no consumer (`consumer.on(...)`); as falhas do loop
de consumo só aparecem no logger interno. A detecção passa a ser por estado, não
por evento.

**Versão:** `2.0.9` → `2.1.9`. Campo novo em API pública, sem quebra: bump de
minor, mantendo o patch (não zerar patch em bump de minor/major).

## Critério de aceite

-   [x] `getHealth().partitionsAssigned` retorna o número de partições atribuídas.
-   [x] Retorna `null` quando não há consumer (`init(true, false)`).
-   [x] Retorna `null` quando `assignment()` lança (consumer não conectado).
-   [x] Retorna `0` quando o consumer está conectado sem partições.
-   [x] `send()` com 3 argumentos emite `console.warn` uma única vez.
-   [x] `sendBatch()` com 2 argumentos emite `console.warn` uma única vez.
-   [x] As assinaturas documentadas não emitem aviso.
-   [x] `npm run lint` e `npm test` (unitários) passam.

## Fora de escopo

-   Publicação no npm da `2.1.9` — passo de release separado.
-   Reintrodução de `consumer_crash` — sem suporte no backend.
-   Wrapper para `commitOffsets`, `seek`, `pause`, `resume` e para o conteúdo de
    `assignment()`; só a contagem é exposta.

## Atualizações de documentação necessárias

-   [x] `docs/LIB_UPGRADE.md` — nova transformação obrigatória 4
        (`consumer_crash`), ressalva em "O que preservar", versão e checklist.
-   [x] `docs/API_REFERENCE.md` — tabela de campos de `getHealth()`, ausência de
        evento de crash, aviso de argumentos ignorados, limites do wrapper e versão.
-   [x] `README.md` — campo `partitionsAssigned`.
-   [x] `CLAUDE.md` — assinatura de `send`/`sendBatch` e forma de `getHealth()`.
